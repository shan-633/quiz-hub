# 知序题库交换协议 v1.0

本协议用于把一份完整题库导入知序 WebApp。它描述题目内容、图文排版、作答方式和评分规则；文件不包含用户、学生答案、数据库主键或登录信息。协议版本：**1.0**，发布日期：2026-10-20。

## 1. 文件与流程

使用 UTF-8 编码的单个 JSON 文件，推荐命名 `专题名称.zqb.json`，普通 `.json` 也接受。UTF-8 BOM 可有可无。不支持注释、尾随逗号、NaN、Infinity、JSON5、Excel、Word、PDF 或 ZIP 的直接识别。数学和 Markdown 字符串必须遵守 JSON 转义：换行为 `\n`，LaTeX 中的反斜杠写成 `\\`。

管理员进入「题库管理 → 导入题库」，下载模板，选择文件，点击「校验文件」。服务器检查结构、题型、答案、图片和分值；只有**全部通过**，才显示可导入状态。管理员可逐题预览，再选择「保存为草稿」或「导入并发布」。校验阶段不会保存图片或创建题库。

本版选择 JSON，是因为题干和小问具有树状结构，表格单元格难以完整表达；图片随文件携带，文件换机器后仍可导入。协议不执行脚本、不抓取网络图片。HTML不渲染；Markdown图片语法禁止，请使用image内容块。文字中的普通链接可显示，图片与公式应分别使用指定结构。

## 2. 顶层结构

| 字段        | 必填 | 规则                                   |
| ----------- | ---- | -------------------------------------- |
| `format`    | 是   | 固定字符串 `zhixu.question-bank`       |
| `version`   | 是   | 固定字符串 `1.0`，不支持的版本拒绝导入 |
| `bank`      | 是   | 题库元信息，见下节                     |
| `questions` | 是   | 1—200道题，数组顺序为文件中的题序      |
| `assets`    | 否   | 图片数组，默认空数组，最多100张        |

所有对象都拒绝未定义字段，防止字段拼写错误被悄悄忽略。文件里不要填写 `bankId`、`state`、`latestVersion`、题目的 `version` 等系统字段。

### bank：题库信息

| 字段          | 必填/默认   | 规则                                                      |
| ------------- | ----------- | --------------------------------------------------------- |
| `title`       | 必填        | 非空，最多200字符                                         |
| `description` | 默认 `""`   | 简介，最多3000字符                                        |
| `chapter`     | 默认 `""`   | 学段与专题，最多100字符，如「九年级 · 电学」              |
| `minutes`     | 默认30      | 预计练习分钟数，1—600整数                                 |
| `accent`      | 默认 `exam` | `mechanics`、`electric`、`buoyancy`、`exam`，选择封面主题 |

## 3. 一个可直接导入的最小文件

以下是一道**协议演示题，不是真题卷**。保存为 UTF-8 `.json` 后即可校验。

```json
{
  "format": "zhixu.question-bank",
  "version": "1.0",
  "bank": { "title": "协议演示 · 最小题库", "minutes": 5 },
  "questions": [
    {
      "id": "q1",
      "type": "single",
      "title": "力的单位",
      "score": 2,
      "content": [{ "id": "stem", "type": "paragraph", "text": "下列哪个是力的国际单位？" }],
      "options": [
        { "id": "a", "text": "牛顿" },
        { "id": "b", "text": "焦耳" }
      ],
      "solution": { "choices": ["a"], "explanation": "力的国际单位是牛顿，符号为N。" }
    }
  ]
}
```

配套下载：`minimal.zqb.json`（最小模板）、`six-types.zqb.json`（六题型各一题，明确区分演示与原题来源）、`beijing-2022.zqb.json`（整套2022北京物理真题及原图）。管理员导入弹窗提供全部下载入口。原卷来源和校读说明见项目 `docs/beijing-2022-real/逐题分析与来源.md`；北京文件导入为独立题库，不覆盖已安装的真题卷。

## 4. question：一道题的结构

| 字段              | 必填/默认    | 说明                                                                    |
| ----------------- | ------------ | ----------------------------------------------------------------------- |
| `id`              | 必填         | 文件内题号标识，如 `q01`，同一文件不重复                                |
| `type`            | 必填         | 六类题型之一，见下表                                                    |
| `title`           | 必填         | 非空，最多300字符                                                       |
| `score`           | 必填         | 大于0，最多1000分；小数允许                                             |
| `content`         | 必填         | 1—100个顶层内容块，可组合嵌套                                           |
| `solution`        | 必填         | 标准答案和非空解析，见第7节                                             |
| `difficulty`      | 默认「基础」 | 难度标签，最多50字符                                                    |
| `tags`            | 默认 `[]`    | 最多20个知识点标签，每个最多100字符                                     |
| `source`          | 可选         | 最多1000字符，记录年份、题号、来源及校读说明                            |
| `options`         | 默认 `[]`    | 顶层选择题选项；其他题型须为空                                          |
| `blanks`          | 默认 `[]`    | 全题共享的稳定填空定义                                                  |
| `multipleScoring` | 可选         | 仅顶层多选题：`exact` 或 `half`，缺省按全对计分                         |
| `allowedModes`    | 可选         | 开放作答方式：`text`、`drawing`、`photo`，1—3项，不重复；计算题必须填写 |

### 题型与作答控件

| type          | 题型     | 约束与行为                                                                   |
| ------------- | -------- | ---------------------------------------------------------------------------- |
| `single`      | 单选     | 至少2个非空选项；1个正确选项；不能混入填空/子题                              |
| `multiple`    | 多选     | 至少2个选项，至少1个正确答案；不能混入填空/子题                              |
| `fill`        | 填空     | 用 `{{blank-id}}` 在段落/表格中放置填空，不使用子题；填空分值合计=总分       |
| `experiment`  | 实验     | 可包含填空、选择小问和开放小问；复用实验混合模板                             |
| `reading`     | 科普阅读 | 共享材料、图片，再放置各类小问；复用阅读混合模板                             |
| `calculation` | 计算大题 | 只有题干与整体开放作答区；不设填空/子题；支持文字、Markdown/公式、手写、照片 |

如果一题同时有客观填空和论证，请使用 `experiment` 或 `reading`，将论证放进独立 `open` 小问。不要把不能自动判分的论证伪装成一项标准字符串答案。

## 5. ID、内容块和排版

所有 ID 由1—128位英文字母、数字、下划线、短横线组成，区分大小写；不使用空格或中文。`__proto__`、`prototype`、`constructor`、`toString`、`valueOf`、`hasOwnProperty` 等对象原型名称为保留ID，机器Schema给出完整排除表达式。

题目ID、图片ID分别在文件内唯一；内容块ID与填空ID分别在单题内唯一；计分的选择/开放小问ID不能与填空ID相同；选项ID在所属选项组内唯一。不同题目可以复用 `stem`、`a`、`b1` 等局部ID。导入时服务器为题库、题目和图片分配全新内部ID，并重新关联图片；局部填空和小问ID保持稳定。

所有内容块都必须有 `id` 和 `type`。段落最多100000字符；独立公式最多10000字符。表格最多20列、100数据行，单元格最多5000字符；图文组合及子题最多50个直接子块。

| type          | 其他字段                                                    | 说明                                                                             |
| ------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `paragraph`   | `text`                                                      | Markdown段落，支持 `$...$` 行内公式、`$$...$$` 独立公式及稳定填空                |
| `formula`     | `latex`                                                     | LaTeX公式字符串，不需要外围美元符号                                              |
| `image`       | `assetId`、`alt`；可选 `caption`、`width`                   | 仅引用assets图片，alt为必填替代文字；caption默认空；width为10—100百分比，默认100 |
| `table`       | `headers`、`rows`                                           | 至少1列表头，数据每行列数等于表头；支持文本、公式和填空                          |
| `group`       | `layout`、`children`                                        | `stack`上下排，`mediaAside`宽屏图文并排；窄屏自适应；children非空                |
| `subquestion` | `label`、`score`、`responseKind`、`children`；可选`options` | 仅实验/阅读混合题使用，见下节；children非空                                      |

示例（反斜杠使用JSON转义）：

```json
{
  "id": "formula1",
  "type": "formula",
  "latex": "P=\\frac{W}{t}"
}
```

### 子题 subquestion

`label` 为非空小问名称，最多200字符；`score` 大于0，最多100。不允许子题嵌套子题，子题内部仍可用group组织图文。

- `responseKind: "blanks"`：children中引用本小问填空，其填空分值和必须等于小问score。不设置options。答案存放在全题solution.blanks。
- `single` / `multiple`：options中填写至少两个非空选项，每项为 `{ "id": "a", "text": "选项内容" }`；正确答案放 `solution.partChoices[小问ID]`。此小问不能再放填空。
- `open`：独立文字/手写/照片区，人工评阅；不能设置选项、choices或内嵌填空。参考解答写入solution.explanation。

**分值不重复计算**：全题总分 = 所有blank.score + 所有非blanks子题.score。blanks子题的score只是组内小计，不再次相加；总分比较容差0.001分。顶层选择题和计算题直接按question.score。

## 6. 填空与匹配规则

```json
{
  "content": [{ "id": "p1", "type": "paragraph", "text": "密度为 {{rho}} g/cm³。" }],
  "blanks": [{ "id": "rho", "label": "密度", "kind": "number", "score": 2, "unit": "g/cm³" }],
  "solution": {
    "blanks": { "rho": { "accepted": ["2.7"], "tolerance": 0.01 } },
    "explanation": "由密度公式计算，结果为2.7 g/cm³。"
  }
}
```

这是填空字段片段，完整题目仍需id、type、title、score等必填项。

每个填空必须在正文段落或表格中以 `{{ID}}` **恰好出现一次**，不能有未定义引用或定义后未使用的空格。label用于无障碍标签，必填且最多200字符；unit为可选提示，不自动从答案中移除单位。

| kind     | 行为                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------------- |
| `text`   | 与accepted中的任一字符串匹配；默认只去首尾空白，`ignoreWhitespace:true`忽略全部空白；不自动忽略大小写             |
| `number` | accepted仍写字符串，每项必须可转换为有限数值；比较绝对误差，tolerance默认0且不小于0、不超过1e12；填写时只输入数值 |
| `manual` | 非空答案待人工评阅，不做字符串自动判分；标准匹配规则可省略，参考答案放解析                                        |

每空score须大于0且不超过100分。自动判分填空必须提供非空accepted，最多30个可接受答案、每个最多1000字符。不支持正则表达式或执行代码匹配。

## 7. solution：标准答案与评分

| 字段          | 默认/说明                                                                              |
| ------------- | -------------------------------------------------------------------------------------- |
| `choices`     | 默认 `[]`，仅顶层单选/多选；填写选项ID，不能填写展示字母或题号，除非选项ID本来就是该值 |
| `blanks`      | 默认 `{}`，以填空ID为键，值为accepted/tolerance/ignoreWhitespace规则                   |
| `partChoices` | 可选对象，以选择小问ID为键，值为正确选项ID数组                                         |
| `explanation` | 必填非空参考解析，最多100000字符，支持Markdown与公式                                   |

选项和正确答案ID不重复，答案必须引用所属题/小问中的真实选项。不得为不存在的空格、小问配置答案。`multipleScoring: "half"` 时全对得满分，选中正确选项的非空真子集得一半，错选或未选得0；`exact`时仅全对得分。子题多选采用全对计分，不支持子题半分设置。

开放论证、实验步骤、manual填空及计算过程需人工评阅，校验报告会提示。当前应用尚无教师评分工作台；协议导入不会增加AI判卷能力。学生进行中作答API不返回solution。

## 8. assets：图片随文件携带

```json
{
  "id": "fig17",
  "mimeType": "image/webp",
  "name": "原卷图17.webp",
  "data": "这里替换为原始文件的标准Base64字符串"
}
```

此处为示意片段，data占位文字不能通过校验。最可靠的完整示例是下载的北京原图真题文件。

- mimeType仅为 `image/png`、`image/jpeg`、`image/webp`。不接受SVG、GIF、动画、多页图片、路径、网络URL或data URL。
- data必须为原始字节的标准Base64编码：无 `data:...;base64,` 前缀、无空白；单图解码后不超过5 MiB，最多2500万像素。
- name为可选人类可读名称，最多255字符，不作为保存路径。客户端文件名不会用于磁盘写入。
- 所有image块必须引用已声明图片，所有声明图片必须被使用。相同图片在一份文件内只存一份，可被多题多次引用。
- 服务器检查真实格式、像素尺寸并完整解码，损坏图片阻断整份导入。**入库保存原始字节，不重新压缩、重绘或删除水印**。图片宽高由服务器读取，文件中不填intrinsicWidth/intrinsicHeight。
- PNG/JPEG/WebP可以包含来源水印与版权信息；请在source和caption中标注真实来源，避免把协议演示题当作原卷真题。

Python制作图片字段：`base64.b64encode(Path("原图.webp").read_bytes()).decode("ascii")`。本地路径只在制作者电脑读取，不放进导入文件。浏览器内不需要安装Python。

## 9. 限制、错误与完整性

文件20 MiB（20971520字节），单图5 MiB；最多200题、100图。对象/数组结构深度不超过24层，总节点不超过100000；单题补齐系统字段和图片宽高后不能超过20000节点，单题最多1000个内容块、全文件最多10000块。这些限制与编辑器保存保持兼容。大题库请按章节拆分。JSON Schema能校验字段和基本范围；图片实际解码、ID/引用、题型组合、公式和分值仍须以服务器完整校验为准。

错误包含path、code、message，例如：

```json
{
  "valid": false,
  "errors": [
    { "path": "$.questions[0]", "code": "question", "message": "填空及子题分值之和必须等于总分" }
  ],
  "warnings": []
}
```

下标从0开始；questions[0]就是第一题。错误列表最多显示100项，修复后再校验。图片解码错误可额外列出各资源的问题。警告说明人工评阅，不阻断导入。校验失败没有任何题目入库；提交时重新完整校验，不能绕过。

每次提交以**原文件文本（仅移除开头BOM）的UTF-8 SHA256**识别重复。同样的文件多次提交，包括网络中断重试或同时提交，仅导入一次；返回原有题库，不改变其发布/归档状态。调整空格、换行或内容会产生新摘要，视为另一份文件，不是“更新原题库”。需要编辑已导入内容请使用管理员编辑器。

导入默认是草稿，题库与各题均为草稿，学生不可见；可以在题目管理中校对后逐题发布，再发布题库。选择「导入并发布」时会同时生成题目的不可变v1和公开题库。管理员题数包含未归档草稿，学生目录仅统计已发布题目。

提交中所有数据库写入采用一个事务，写入失败回滚并清理本次已创建图片；既有题库、题目和历史作答不覆盖。这里保证一次请求的正常失败回滚，不宣称跨数据库与文件系统的断电级分布式事务；突发断电可能遗留未关联文件，不会形成部分公开题库。

## 10. API与生成工具

上传的两个接口均需管理员会话Cookie、可信来源和 `x-csrf-token`：

| 接口                                   | multipart字段                                                            | 结果                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `POST /api/admin/bank-import/validate` | `file`                                                                   | 200报告：valid、errors、warnings；通过时含digest、summary、preview，已导入则含existing |
| `POST /api/admin/bank-import/commit`   | `file`、校验返回的`digest`；可选`publish`字符串`true`/`false`，默认false | 新建201；同文件重试200，返回bankId、title、state、questionCount、reused                |

文件扩展名须.json；请求文件字段只能是file。错误格式422、权限401/403、超限413、提交摘要不一致409；500表示提交失败，客户端可用原文件重试。报告preview含教师答案，仅管理员接口可访问；不要转发给学生端。

项目中的 `shared/bankImport.ts` 是运行时协议定义；`content-assets/import/question-bank-v1.schema.json` 是对应JSON Schema。`scripts/build-import-examples.ts` 生成静态文档、机器Schema和三个示例；新增协议版本应同步Schema、介绍文档、示例和测试。当前不支持更高版本的自动兼容或迁移。

下载接口为 `GET /api/admin/bank-import/files/文件名`，同样仅限管理员。示例含标准答案，文件保存在非公开资源目录，不能作为学生可访问的静态文件部署。
