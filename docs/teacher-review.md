# 教师收卷与批改（3.2）

## 使用流程

学生完成试卷或题库练习后提交，答案锁定，显示「已交卷，教师已收到」。教师登录 [收卷与批改](http://localhost:3001/teacher) 后，按学生、题库/试卷、交卷时间查看收卷记录。点击「进入批改」查看交卷时的题目版本与原始作答；答题卡可以切题。

每种题型都可判正确、错误或部分正确。正确自动填满分，错误自动填0分，部分正确可填写0与满分之间的数值，支持小数。正确答案默认填入该题的标准答案，可针对本次作答补充；教师评语支持Markdown与数学公式。点击「保存本题批改」保存到服务器；切题时有未保存内容会提示。正确答案与评语不修改题库。

所有题目完成判定后点击「发布批改结果」，确认总分后发布并锁定。学生刷新批改结果或打开「我的作答」即可查看成绩和反馈。自动初评的选择题可直接采用，也可逐题覆盖，填写评语后保存。发布前学生接口不会返回批改分数、题库标准答案或教师反馈。

教师演示账号 `teacher / Teacher123!`，管理员 `admin / Admin123!` 也能批改。教师与管理员均可创建、维护、发布及导入题库。当前为本地单教学空间，教师可查看本系统内全部已交卷记录；没有班级、分配教师或学校隔离。教师不能查看未交卷的作答、未提交的照片或没有引用在答案中的附件。

## 自动初评规则

交卷时检查**本次作答引用的题目快照**，而不是后来修改的题库。所有题的标准答案都完整才开启初评：

| 作答结构   | 完整性要求                                               | 自动初评                          |
| ---------- | -------------------------------------------------------- | --------------------------------- |
| 单选、多选 | 正确选项非空、无重复且来自当前选项，单选只有一个         | 是；多选沿用题目精确/漏选半分规则 |
| 填空       | 每空有非空可接受答案，数值答案有效；人工填空有参考解析   | 否                                |
| 实验、阅读 | 所有空有答案，选择小问有有效选项答案，开放小问有参考解析 | 只评选择小问，其他作答点人工      |
| 计算       | 有非空参考解析/解题过程                                  | 否                                |

任何一道题的标准答案缺失，全卷转人工；题库本身仍可在草稿阶段录入不完整答案。发布题库继续沿用现有的完整性校验。所有人工作答点均等待教师判定，即使学生留空，也不会自动判错。

自动结果仍是教师端的初评草稿，教师发布后才向学生开放。混合题显示已初评的选择部分得分，教师填写本题最终总分（包含选择小问的分数），不能再重复叠加初评分。

## 保存、版本与历史记录

批改按整份答卷的 `review.revision` 检查版本。两个窗口同时批改时，后保存的旧版本收到409，表单文字保留；点击「载入最新批改」核对后再保存。未保存的批改不会自动同步到服务器，离开页面前应点击保存。

旧版已经提交的记录不自动改变，列在「历史记录」。教师查看后可主动选择「发起教师复核」；确认后重新生成选择题初评，其余题型等待人工，学生在重新发布前只看到收卷确认。原始答案和题目快照保留。发布后的批改只读；本版本不提供再次修改已发布成绩的功能。

## 前后端协议

新增 `User.role=teacher`。`Attempt.status` 仍为 `active/submitted`；可选 `review` 表示新流程，缺失代表历史记录。`review.state` 为 `pending/in_progress/published`，附revision、自动初评条件/数量/说明、收卷时间、发布时间和发布教师。`teacherFeedback[questionId]` 保存判定、最终分数、正确答案、评语、教师与保存时间。题目快照不变。

| 接口                                        | 用途                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `GET /api/teacher/attempts`                 | 教师收卷箱，含学生信息、试卷/题库类型、批改进度                                |
| `GET /api/teacher/attempts/:id`             | 已交卷的完整快照、答案、初评与教师反馈                                         |
| `POST /api/teacher/attempts/:id/start`      | 历史记录进入复核，body为expectedRevision:0                                     |
| `PUT /api/teacher/attempts/:id/grades/:qid` | 保存本题判定，body包含expectedRevision、verdict、score、correctAnswer、comment |
| `POST /api/teacher/attempts/:id/publish`    | 全部完成后发布，body包含expectedRevision                                       |

所有接口要求teacher/admin角色；写操作校验会话、可信来源与CSRF。保存/发布均在SQLite事务中执行。`Grade.source` 区分 `auto/teacher/pending/mixed`。学生交卷接口幂等，不会清除教师已经保存或发布的批改。学生列表与详情在发布前都隐藏得分；本人仍能查看锁定的原始作答。
