# 教师进度、收卷与批改（4.0）

## 未交卷进度

教师工作台新增独立「进行中」分区，记录学生已开始但尚未交卷的试卷和题库练习。每条显示学生姓名/账号、题库类型、完整填答题数、部分填答题数、未作答题数、完成百分比、开始时间及最近同步时间；支持搜索学生或试卷。未交卷不代表学生当前在线，最近同步时间代表服务器保存的作答时间。

学生停顿700ms同步，持续输入最长每2秒发起同步；文字、选项、填空、手写共用草稿保存，照片上传成功后同步。切到后台或离开作答页会尝试立即保存，强制关闭或断网时无法保证最后一次网络请求完成，本机草稿会在再次打开练习时恢复；恢复网络后补传。离线本机的内容须同步成功后教师才能看到。

页面可见时建立SSE连接，先获取最新快照，再接收学生保存后的进度变化，无需定时刷新。隐藏时暂停连接，返回重新获取快照。网络异常会提示并保留上次数据，自动重连，也可立即重试；登录失效则清除旧进度并提供教师登录入口。填答比例表示是否已填入内容，不代表正确率：单/多选选过即算已填答，多空或混合题全部作答点有内容才计完整；只填部分另计。空白画板、空字符串及仅标记不算填答。清空答案后比例下降，100%也仍为未交卷，必须由学生主动交卷。

交卷后记录从进行中移除；切换「待处理」重新读取收卷箱即可进入批改。进行中接口只返回进度元数据，不能读取原始答案或提前批改。

## 使用流程

学生完成试卷或题库练习后提交，答案锁定，显示「已交卷，教师已收到」。教师登录 [收卷与批改](http://localhost:3001/teacher) 后，按学生、题库/试卷、交卷时间查看收卷记录。点击「进入批改」查看交卷时的题目版本与原始作答；答题卡可以切题。

每种题型都可判正确、错误或部分正确。正确自动填满分，错误自动填0分，部分正确可填写0与满分之间的数值，支持小数。正确答案默认填入该题的标准答案，可针对本次作答补充；教师评语支持Markdown与数学公式。点击「保存本题批改」保存到服务器；切题时有未保存内容会提示。正确答案与评语不修改题库。

所有题目完成判定后点击「发布批改结果」，确认总分后发布并锁定。学生刷新批改结果或打开「我的作答」即可查看成绩和反馈。自动初评的选择题可直接采用，也可逐题覆盖，填写评语后保存。发布前学生接口不会返回批改分数、题库标准答案或教师反馈。

教师演示账号 `teacher / Teacher123!`，可创建、维护、发布及导入自己的题库；[题库入口](http://localhost:3001/teacher/library)。管理员管理账号及多对多师生关系，学生可关联多位教师；教师只能查看自己题库的题目和本人试卷上当前关联学生的进度/答卷，不能查看其他教师的题目或该学生在其他教师处的作答。教师不能查看未交卷的原始作答、未提交的照片或没有引用在答案中的附件。旧管理员保持停用，新管理员通过本机初始化，详见[账号与聊天说明](roles-and-chat.md)。

## 自动初评规则

交卷时检查**本次作答引用的题目快照**，而不是后来修改的题库。所有题的标准答案都完整才开启初评：

| 作答结构   | 完整性要求                                               | 自动初评                          |
| ---------- | -------------------------------------------------------- | --------------------------------- |
| 单选、多选 | 正确选项非空、无重复且来自当前选项，单选只有一个         | 是；多选沿用题目精确/漏选半分规则 |
| 填空       | 每空有非空可接受答案，数值答案有效；人工填空有参考解析   | 否                                |
| 实验、阅读 | 所有空有答案，选择小问有有效选项答案，开放小问有参考解析 | 只评选择小问，其他作答点人工      |
| 计算       | 有非空参考解析/解题过程                                  | 否                                |

任何一道题的标准答案缺失，全卷转人工；题库本身仍可在草稿阶段录入不完整答案。发布题库继续沿用现有的完整性校验。所有人工作答点均等待教师判定，即使学生留空，也不会自动判错。

自动结果仍是教师端的初评草稿，教师发布后才向学生开放。混合题显示已初评的选择部分得分，教师填写本题最终总分（包含选择小问的分数），不能再重复叠加初评分。

## 保存、版本与历史记录

批改按整份答卷的 `review.revision` 检查版本。两个窗口同时批改时，后保存的旧版本收到409，表单文字保留；点击「载入最新批改」核对后再保存。未保存的批改不会自动同步到服务器，离开页面前应点击保存。

旧版已经提交的记录不自动改变，列在「历史记录」。教师查看后可主动选择「发起教师复核」；确认后重新生成选择题初评，其余题型等待人工，学生在重新发布前只看到收卷确认。原始答案和题目快照保留。发布后的批改只读；本版本不提供再次修改已发布成绩的功能。

## 前后端协议

`User.role` 仅包含student/teacher；旧管理员记录只保留历史归属，不允许认证。`Attempt.status` 仍为 `active/submitted`；可选 `review` 表示新流程，缺失代表历史记录。`review.state` 为 `pending/in_progress/published`，附revision、自动初评条件/数量/说明、收卷时间、发布时间和发布教师。`teacherFeedback[questionId]` 保存判定、最终分数、正确答案、评语、教师与保存时间。题目快照不变。

| 接口                                        | 用途                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `GET /api/teacher/attempts`                 | 教师收卷箱，含学生信息、试卷/题库类型、批改进度                                |
| `GET /api/teacher/progress`                 | 未交卷进度元数据，按最近同步时间倒序；无原始答案，响应禁止缓存                 |
| `GET /api/teacher/progress/events`          | SSE：snapshot初始快照、progress增量、heartbeat心跳、session-expired登录失效 |
| `GET /api/teacher/attempts/:id`             | 已交卷的完整快照、答案、初评与教师反馈                                         |
| `POST /api/teacher/attempts/:id/start`      | 历史记录进入复核，body为expectedRevision:0                                     |
| `PUT /api/teacher/attempts/:id/grades/:qid` | 保存本题判定，body包含expectedRevision、verdict、score、correctAnswer、comment |
| `POST /api/teacher/attempts/:id/publish`    | 全部完成后发布，body包含expectedRevision                                       |

所有教学管理接口要求teacher角色；写操作校验会话、可信来源与CSRF。保存/发布均在SQLite事务中执行。`Grade.source` 区分 `auto/teacher/pending/mixed`。学生交卷接口幂等，不会清除教师已经保存或发布的批改。学生列表与详情在发布前都隐藏得分；本人仍能查看锁定的原始作答。

## 实时进度的存储与部署

`ProgressStore`在同一个SQLite数据库维护仅含未交卷记录的`attempt_progress`摘要表。首次升级以事务逐条回填并记录迁移标记，之后启动不再扫描原始作答。保存答案和摘要在同一事务完成，提交后才广播；交卷或删除时移除摘要。教师查询只读取摘要及学生/题库元数据，避免解析历史答案和手写笔迹。原始教学文档及题目版本不改写。

连接每15秒心跳，并在心跳和推送时复查教师会话；慢连接缓冲超过1MiB会关闭。客户端建连20秒、连接静默45秒会发起恢复，身份探测5秒超时后继续重连，重试间隔从1秒递增至15秒；成功后恢复初始间隔。重连总是获取完整快照，不依赖断开期间的事件回放。

当前运行方式为单后端进程，事件订阅保存在进程内。后续若改为多个后端进程，需要共享事件通道；写入作答应经过应用的`ProgressStore`，直接修改SQLite文档不会维护摘要。通用`Store`仍用于原有工具和历史压测基线。

反向代理需允许长连接并关闭SSE缓冲；接口已设置`X-Accel-Buffering: no`及禁止缓存。前后端分别部署时沿用`VITE_API_URL`与准确的`APP_ORIGIN`配置，EventSource携带Cookie，响应保留凭据CORS头。实际配置和数据备份方法见README。
