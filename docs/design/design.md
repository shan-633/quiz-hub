# 知序 · 物理练习 WebApp 设计提案

日期：2026-10-20。状态：调研与原型已完成，设计待用户确认；尚未开始产品代码、依赖安装或部署。

## 1. 目标和边界

用户要求：制作手机、iPad、PC 响应式答题 WebApp，前后分离。学生从首页选择试卷或题库后，进入包含多道题的答题页面；支持单选、多选、填空、实验题、计算题。计算题支持文字/Markdown、手写、拍照。管理员创建题库、录入和排版题目。

本提案假设：中文、初中物理、先提供可运行的首版和完整源码。品牌名“知序”为暂定，可修改。首版同时包含学生练习与后台录题完整流程。既有工作目录中的试卷、截图不会被自动导入；示例内容使用自编题，并标明示例。

不纳入首版：AI 识题、自动判断计算过程、Word/PDF 全自动解析、监考、付费、社交、班级管理。手写与照片不依赖 OCR，避免把识别能力作为基础答题的前提。

## 2. 同类产品调研

| --- | --- | --- |

| Gradescope | 在线题目支持选择、短答、图片/文件上传；纸面作业按题定位答案 | 计算题图片直接属于当前题目/小问，上传后可检查顺序和清晰度 |
| ClassMarker | 题库存题、跨试卷复用、富媒体编辑；已保存结果保持原题，改动用于后续作答 | 题目内容版本化，试卷发布和练习开始时固定版本，保留历史答案语义 |

## 3. 方案取舍

1. 基于 Moodle 定制：题库和题型能力成熟，但需要适配既有平台结构，移动端计算题体验改造较多。
2. 直接把 PDF/题目截图作为整题：导入快，但正文难以响应式重排，无法自然插入空格和复用子题。保留截图块作为兼容入口，不作为唯一数据模型。
3. 自建结构化题目＋共享渲染器（推荐）：初期需要编辑器与模型设计，但能统一学生端、后台预览、题目版本和混合答案，最适合当前需求。

## 4. 学生端页面

### 首页 /library

搜索、试卷/题库筛选、章节/知识点标签、继续上次练习。卡片展示真实题量、预计时长和练习状态，不摆放无数据来源的学习统计。题库是可维护的题目集合；试卷是确定顺序和分值的一组题目。

### 答题 /attempts/:id

一个练习包含多道题。默认连续题目卡片，答题卡可以定位题目，支持上一题/下一题、标记稍后检查。桌面保留侧边题号目录；小屏折叠为题号抽屉或横向导航，不挤压正文。

题卡展示题号、题型、分值、公共材料、子问题及作答区。选择题使用整行可点选的选项；多选明确标注；填空按 stable blankId 保存；实验题可以同时包含文字空格、数值空格和子选择题。输入区同时显示单位和必要提示。

页面状态必须区分“正在保存”“已保存到服务器”“仅保存在本机”“保存失败”。提交前列出未答题，用户可返回补答或明确确认提交；提交成功后才锁定答案。练习模式提交后展示可判题结果与解析；主观题标记“待评阅”，不伪造得分。

### 我的作答 /attempts

只列出自己的进行中和已提交记录，可继续作答或只读查看。已提交状态不能被旧的自动保存请求覆盖。

## 5. 计算题的三种输入

三种入口属于同一答案，可混合保存；切换选项卡不能清空其他入口。最终提交前展示答案总览，避免用户误以为只提交当前标签页。

| 入口 | 首版体验 | 数据 |
| --- | --- | --- |
| 文字与公式 | 普通文字直接输入；Markdown 编辑/预览；KaTeX 数学公式；常用上下标、分式提示；清楚区分草稿与预览 | 原始 Markdown＋版本号；展示时清理危险 HTML |
| 手写 | 画笔、颜色、粗细、笔迹橡皮、撤销/重做、方格纸、多页；可扩展书写区；横竖屏恢复 | 笔迹点序列（位置、压力、时间）、页尺寸和页 ID＋生成的预览图片 |
| 拍照上传 | 拍照/相册、预览、旋转、排序、删除、重试；支持多张；每张绑定题目或小问 | 上传资源 ID＋页序号＋旋转角度＋题目/小问归属 |

默认入口：有键盘的桌面建议文字；检测到笔输入时建议手写；手机提供明显的拍照入口。用户可随时手动选择，不强制按设备分类。

手写使用 Pointer Events，正确处理 pointercancel、pointer capture 和 devicePixelRatio；笔迹坐标独立于显示尺寸。提供“仅笔书写”模式减少手掌误触、手指用于滚动。浏览器和设备的防误触能力存在差异，不能承诺与原生笔记软件完全一致，必须做真机验收。绘图区域设置触控行为，页面其余区域保留正常滚动。离开页面前即使网络失败，也应在本机保留笔迹。

拍照首先使用系统文件选择器和 capture 提示，不强制启动自定义摄像头；浏览器是否直接打开相机由系统决定。首版支持 JPEG/PNG/WebP，单张最大 10MB、每题最多 10 张，前后端均校验实际文件类型和大小，生成缩略图，保留清晰可读的解题图。HEIC 若无法解码，必须明确提示转为兼容格式，不能静默失败。相机入口需要在 HTTPS 与真实设备上验证。

裁剪、透视矫正、OCR 可作为下一版能力；首版不把“手机文件选择器”的存在当作这些能力已经完成。

## 6. 可复用题干模型

题目不是一段任意 HTML，也不是以固定横坐标摆放的打印页面，而是一个有版本的内容树。

```text
QuestionVersion
  id / questionId / version / type / title
  grade / chapter / tags / difficulty / source / score
  content: ContentBlock[]
  responseSchema: 选项、空格、子题或开放回答配置
  solution: 标准答案、判题规则、解析（仅后台/允许查看结果时返回）
  publicationState: draft | published | archived

ContentBlock
  paragraph: inline 节点数组（文字、公式、blank 引用）
  formula: LaTeX 源码＋行内/独立显示
  image: resourceId＋原始尺寸＋alt＋caption＋展示宽度
  table: 行列＋单元格内容节点（允许文字、公式、空格）
  group: 子块＋stack 或 mediaAside 布局
  subquestion: 稳定 ID＋标题＋子内容块＋作答配置＋分值
```

第一版布局只提供“顺序排列”和“图文并排”。图文并排在手机自动转为上下排列；公式、图片不得撑破视口；宽表格允许自身横向滚动。避免自由绝对定位编辑器，因为它难以兼顾移动端与印刷版式。

同一个 QuestionRenderer 用于学生端和后台预览。填空保存时使用 blankId 而不是“第几个空”，选项使用 optionId；重排不会错配答案。父子分值按同一规则汇总，发布时校验总分。图片本身也可作为原题截图块，但无法编辑图中文字或在图内部插入响应式输入框。

## 7. 管理员端

页面：题库列表、创建/编辑题库、题目列表、题目编辑器、试卷管理。

题目编辑器采用“基本信息 → 内容 → 答案与解析”的结构，右侧实时预览。可添加、复制、删除、拖动内容块，并提供上下移动按钮以支持键盘和触屏。复杂内容先用标准布局模板录入，不要求教师编辑 JSON。

题型模板：单选、多选、填空、实验、计算。可插入图片、公式和表格；点击插入空格自动创建 blankId 与答案设置；实验题使用共享题干和子问题；计算题设置允许的输入方式和分步参考答案。

答案配置：单选/多选以选项 ID 判定；填空可设置多个接受答案、是否忽略空白、数值容差和单位要求；开放解释空格与计算题可设为人工评阅。试题类型本身不能决定所有空格都可自动判分。

保存草稿允许未完成；发布必须通过校验：题干非空、图片有效、选项数量合法、单选恰有一个正确项、多选正确集合合法、空格引用与答案一一对应、子题及分值有效、公式可渲染、答案与解析字段按题型完整。发布生成不可变版本；已有作答仍引用旧版本。首版支持题库、题目和试卷的创建/编辑/发布/归档，避免误删除历史引用。

原型图提醒：图内“实验题 6 分”与两空各 2 分是示意稿中的不一致，产品实现将按两空共 4 分或补第三空修正，发布校验也会拦截。学生图里的计算题需要明确 F=200N 才能计算功；正式示例题补齐该条件。图中文字不是可直接导入的题目数据。

## 8. 前后分离架构建议

前端：React＋TypeScript；独立页面路由；共享题目渲染组件；Markdown/KaTeX 展示；Canvas/Pointer Events 手写；IndexedDB 保存未同步草稿与上传队列。

后端：TypeScript HTTP API，建议 Fastify；本地运行采用 SQLite 与独立资源目录，提供初始化示例数据和环境变量示例。数据库访问与资源存储通过适配层隔离，正式托管时可迁移 PostgreSQL 与 S3 兼容存储。前端通过 HTTP JSON API 与后端通信，接口地址可配置，源码、构建与部署入口分开；本地也可以通过前端开发代理访问 API。

优先交付本地可运行版本和源码；公网部署的数据库、对象存储、域名与账号方式需要在实现前确定。若采用 Sites 托管，应使用 Workers 兼容后端与 D1/R2 适配，不能直接把 Fastify/本地磁盘依赖上传到 Workers。两种运行平台必须明确选定，不混用不兼容运行时。

### API 边界

- 公开目录：GET /api/library、GET /api/library/:id。
- 登录会话：POST /api/auth/login、POST /api/auth/logout、GET /api/auth/me。
- 自己的练习：POST /api/attempts、GET /api/attempts、GET /api/attempts/:id。
- 作答保存：PUT /api/attempts/:id/answers/:questionId（携带 expectedRevision）。
- 文件：POST /api/uploads；GET /api/uploads/:id 进行所有权/可见性校验。
- 提交：POST /api/attempts/:id/submit，幂等地转换提交状态。
- 管理：/api/admin/banks、/api/admin/questions、/api/admin/papers 及各自发布接口；全部在服务端校验管理员角色。

### 数据与权限

核心实体为 User、Bank、Question、QuestionVersion、Paper、PaperItem、Attempt、Answer、Asset。Attempt 保存题目版本和顺序快照。Answer 包含 choiceIds、blankValues、markdown、drawingPages、imagePages 与 revision，不把整个答案直接塞进无上限 Base64 字段。

本地首版提供明确标注的学生/管理员演示账号，后端校验密码并创建 HttpOnly 会话；不是通过切换前端菜单来授予管理员权限。对每次读写校验角色与作答所有权，限制登录和上传频率。Cookie 会话的写请求做 CSRF 防护；跨域部署明确 CORS 白名单与凭据策略。上线不得沿用公开演示凭据。

学生开始或继续练习的接口不返回标准答案、解析和判题规则；交卷后由服务器按策略返回结果。不要把“前端隐藏答案”当作防泄漏措施。题目截图和学生答案图片分开管理权限；学生答案不能成为公开静态目录。

### 保存与冲突

编辑先落到本地 IndexedDB，再防抖同步后端；笔迹在每个笔画结束时入本地队列，不能等待离开页面。保存请求按题串行或校验 revision；过期写返回冲突，显示恢复选择，不让晚到请求覆盖新答案。

图片只有上传成功并得到 resourceId 后，才能纳入已同步答案。提交必须等待未同步答案和附件完成；事务锁定快照并防止后续自动保存。网络中断时保留本机内容、明确提示；恢复后重试。跨设备共享仅限成功同步的内容，本地待同步内容不应宣称可跨设备恢复。

## 9. 响应式和无障碍

- 390px 手机：单列正文，选项/按钮易触达，底部导航留出安全区；系统键盘弹出不遮住输入；图片可放大。
- 768/820px iPad 竖屏：优先上下阅读与书写；横屏且内容宽度充足时支持题干与答案两栏。
- 1024px 以上桌面：侧边导航＋宽内容；计算题可两栏；后台编辑/预览并排。
- 管理后台在手机也可编辑基本字段和题目，通过标签切换编辑与预览，不把桌面三列硬缩小。
- 触控目标建议至少 44px；颜色之外同时使用文字和图标表达状态；选择控件与字段有标签；可键盘操作；保留可见焦点。
- 题目图片补充 alt 和图注；公式与宽表格溢出仅在块内部处理；不禁用整页缩放。

## 10. 首版验收标准（计划，尚未执行）

1. 新建题库→录入五种题型→预览→发布→学生首页可见→作答→刷新恢复→提交→查看结果，完成真实前后端链路。
2. 计算题分别输入 Markdown、至少两页手写、至少两张照片；切换标签、切题、刷新、旋转屏幕后内容保留；提交总览包含三种内容。
3. 填空及子题重排不串答案；并排图文在小屏变为上下布局；长公式和表格不造成页面级横向溢出。
4. 服务器重启后题库和答案仍在；断网显示本机保存状态；恢复后同步；版本冲突不会静默丢失内容；提交不漏掉待上传附件。
5. 普通学生不能调用管理员接口、读取他人答案或提前获得标准答案；已提交作答不能再写入。
6. 覆盖 390、820、1440 CSS 像素页面检查；真实 iPad Safari 另验 Apple Pencil、防误触、横竖屏和系统相册/拍照。桌面模拟不能代替真机验收。
7. 执行构建、核心 API 集成测试和关键浏览器流程；记录实际通过项与未验证项，不把计划写成已测试结果。
