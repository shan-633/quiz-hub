# 知序 · 物理练习

中文响应式答题 WebApp，含学生端、教师端、管理员端与师生站内私聊。React + TypeScript + Vite 前端通过 HTTP API 访问 Fastify 后端，SQLite 保存数据。无需外部 AI 服务或 API Key。

当前版本4.2.0支持题库、试卷及班级任务设置开放时间，开放前禁止开始和学生打印；教师可分组推送、设置截止时间和限时作答，服务端到时自动交卷。一个学生可关联多位教师；教师只能访问自己题库的题目和对应答卷，学生登录后只见所属教师已发布的内容。进度和聊天使用独立SSE推送。[此前轮询与摘要＋SSE的三轮压测报告](docs/performance/report.md)保留历史原始数据；实验倍率仅对应当时的隔离原型及数据集，不能直接当作当前整站性能。

## 启动

需要 Node.js 24 或更新版本（已验证 24.15.0）。Windows 解压源码后双击 `START-WEBAPP.cmd`：自动安装依赖、构建并启动。首次安装需要联网。启动后打开 [本地网页版](http://localhost:3001)。关闭启动窗口或 Ctrl+C 停止服务。

也可在项目目录运行：

```powershell
npm ci
npm run build
npm start
```

开发模式：`npm run dev`，打开 http://localhost:5173；前端 5173，API 3001，Vite 代理 `/api`。两个服务可分别用 `npm run dev:client`、`npm run dev:server` 启动。

## 2022北京中考物理真题

首页选择“2022年北京中考物理真题”：真实试卷26题、70分、70分钟，12单选、3多选、8实验、1科普阅读、2计算。不是自行命题的模拟卷。

题干条件、数值、选项顺序及每题分值按原题校录；图1—图24及第11题表格均直接从来源PDF截图，保留原水印，没有AI生成或重绘。网页WebP为无损转换，与PNG截图逐像素一致。来源为用户工作目录已有的公开资料重排PDF，未冒称官方原始扫描版。

逐题分析、来源页、题型、作答方式、原图证据见 `docs/beijing-2022-real/逐题分析与来源.md`；同目录附 `source.pdf`、`image-provenance.json`、`paper.json` 和参考答案校读说明。运行 `node --import tsx scripts/export-real-paper.ts` 可重新导出；`python -X utf8 scripts/verify-real-figures.py` 从附带PDF重渲染，核验每张网页图片的像素来源（需要PyMuPDF和Pillow，网页运行无需Python）。

复用现有单选、多选、实验、阅读和计算模板；实验步骤与推理用独立开放小问保存。多选全对2分、漏选1分、错选/未选0分；新交卷仅选择作答点自动初评，其他作答点由教师批改并统一发布（旧版52分自动判分记录保留）。资料版第20题密度答案“27”按54/20校正为2.7，解析明确说明。逐空分值属于网页配置，不冒称官方评分细则。

此前原创北京模拟卷仅归档，不再显示在公开目录；旧题版本和已有作答保留。演示模式启动默认安装2022真题，重复启动不覆盖教师修改。

## 从格式化文件导入题库

教师点击「导入题库」→ 下载模板 → 选择 `.zqb.json` 或 `.json` → 校验 → 逐题预览 → 保存为草稿或导入并发布。协议 `zhixu.question-bank` v1.0 支持现有六类题型及可复用内容块，PNG/JPEG/WebP图片以Base64内嵌，导入保留原字节。最多200题、100图、20 MiB；错误会指出题目/字段路径，任何错误阻止整份导入。同一教师同文件重试不重复创建，不同教师分别建立自己的题库；既有题库和作答不会被覆盖。

- [协议介绍与完整字段规范](docs/import-protocol-v1.md)
- [JSON Schema](content-assets/import/question-bank-v1.schema.json)
- [最小模板](content-assets/import/minimal.zqb.json)、[六题型示例](content-assets/import/six-types.zqb.json)、[2022北京真题原图包](content-assets/import/beijing-2022.zqb.json)

运行 `node --import tsx scripts/build-import-examples.ts` 可从协议定义与已核对的真题重新生成下载文件。文件校验阶段不写数据库或附件；提交时服务端重校验，事务写入并在失败时清理本次图片。默认草稿需在题目管理中发布各题，再发布题库；选择直接发布时同步创建不可变v1。当前不直接识别Excel/Word/PDF/ZIP，也不执行OCR。

## 使用

教师从[管理学生](http://localhost:3001/teacher/students)创建班级组，再在已发布题库/试卷卡片选择“推送班级”。学生从[班级任务](http://localhost:3001/tasks)进入，倒计时从首次开始计算，刷新不重置；可设绝对截止和答题分钟数，二者取早者。强制到时由服务端交卷，页面锁定后返回任务/历史状态；未强制则允许超时提交并标记迟交。旧题库的“预计时长”仍是建议，不会自动变成强制限制。[完整使用说明](docs/class-assignments.md)。

学生可在首页任意已发布题库/试卷卡片点「打印 PDF」，直接生成固定A4阅读版（正文12磅），随后预览、下载。中文和公式字体随文件嵌入；只含题目与原图，不含答案、个人作答和教师评语。生成不创建或提交练习。[排版与部署说明](docs/print-pdf.md)。

- 学生：首页搜索或筛选题库/试卷 → 开始练习 → 答题与标记 → 提交前检查 → 等待教师批改发布 → 查看成绩、正确答案与评语。我的作答按全部、未答完、待批改、已批改标签分区并显示数量，可继续草稿或重新练习。

- 作答自动保存：输入停顿700ms同步，持续输入最长每2秒发起同步；照片上传后同步，手写笔迹随作答保存。离开页面或切到后台时尝试立即保存，断网内容保留本机，恢复网络后补传。
- 计算题：文字/Markdown/数学公式、多页手写、照片可同时保留。手写支持撤销、重做、笔迹橡皮、加页、加长、放大和仅笔模式；照片支持旋转、排序、删除及失败重试。
- 教师：在教师工作台创建题库 → 新建题目、选择模板 → 排版与答案规则 → 手机/平板/桌面预览 → 保存草稿或发布 → 发布题库。试卷可选择已发布题目版本、调整顺序和分值。
- 题干由段落、公式、图片、表格、图文组合、子题组成。填空用稳定 ID 关联答案；复制内容会生成新 ID。发布时检查空格引用、图片、分值与公式。
- 教师：进入 [收卷与批改](http://localhost:3001/teacher)，接收试卷及题库答题卡，查看原始文字、手写与照片，对所有题型判正确/错误/部分正确，填写分数、正确答案、评语，全部完成后发布。教师也能创建、导入和维护题库。
- 教师「进行中」分区：查看未交卷记录的学生、试卷/题库、完整及部分填答题数、完成比例和最近同步时间；学生保存后通过SSE自动更新，可按学生/试卷搜索。隐藏页面暂停连接，返回或断网恢复后重新获取最新快照。仅展示已同步进度，交卷后从此区移除，切换「待处理」即可批改。
- 全部标准答案完整时，仅选择题及混合题中的选择小问自动初评；其他作答点（含空白答案）等待人工。自动结果可覆盖，学生在发布前看不到答案或分数。历史记录保留原行为，可由教师主动发起复核。详见 [教师批改说明](docs/teacher-review.md)。当前不含OCR或AI 判过程。

草稿自动同步，失败时保存在当前浏览器 IndexedDB。重新联网后自动尝试恢复，也可点击重试。提交会等待正在入库/上传的照片及最后答案保存。多页面冲突会要求选择服务器或本机版本。首次加载页面需要后端，当前不是完整离线 PWA；清除浏览器数据会删除尚未同步的本机草稿。

照片支持 JPEG、PNG、WebP，每题最多 10 张、每张 10MB；服务端实际解码、纠正方向、压缩并生成缩略图。HEIC 需先转换。系统拍照入口取决于设备/浏览器。

## 数据与配置

默认数据在 `data/zhixu.sqlite`，附件在 `data/uploads/`；重启保留，源码压缩包不包含运行数据。备份时先停止服务，再复制整个 `data` 目录；恢复时放回同一位置。

复制 `.env.example` 为 `.env` 可设置 `PORT`、`HOST`、`DATA_DIR`、`APP_ORIGIN`、`SECURE_COOKIE`、`DEMO_MODE`。默认仅监听本机 `127.0.0.1`。`DEMO_MODE=false` 仅停止初始化演示数据，不会删除已有账号；管理员负责创建正式账号并分配师生关系。

前后端分别部署时，前端构建环境设置 `VITE_API_URL`（例如同站点的 API 子域名），后端 `APP_ORIGIN` 设置前端准确来源。请求携带 Cookie，图片也跟随 API 地址。推荐同站点 HTTPS 反向代理：跨站点第三方 Cookie 不属于当前支持范围。正式上线需提供 HTTPS、关闭演示初始化并替换演示账号、配置可信来源和安全 Cookie；本次没有公网部署。

在同一 Wi-Fi 的其他设备访问，需要按实际局域网地址设置 HOST/APP_ORIGIN 并允许本机端口；默认启动地址不能从另一台设备访问。Apple Pencil 压感、防误触和系统相机尚未真机验收。

## 源码与验证

- `client/`：学生端、教师端、管理员端、站内消息、共享渲染器、草稿及附件队列。
- `server/`：认证、教学授权、账号与关系管理、聊天、作答、上传 API 与真实 SQLite 存储。
- `shared/`：结构化题目、答案、发布校验、判分与编辑操作。
- `tests/`：模型、API、组件、角色与教学隔离、聊天、持久化、竞态、原图、结果反馈、打印、历史分区及实时进度回归测试。
- `content-assets/beijing-2022/`：真实试卷原图截图、无损WebP和来源清单。
- `public/diagrams/`：自编物理示意图。
- `docs/design/`：竞品调研、设计方案与 ImageGen 原型。
- `docs/screenshots/`：实际运行页面；`docs/verification.md`：验收范围与限制。

`npm test` 运行测试；`npm run build` 执行 TypeScript 检查和生产构建。`npm run format` 格式化源码。服务端会校验角色、作答/附件所有权、CSRF、来源与 revision；进行中及等待教师发布的学生作答不会获得标准答案或批改草稿。已发布题目保留不可变版本，旧作答不随后台修改改变。

三个版本为 Git 标签 `v1.0.0`、`v2.0.0`、`v3.0.0`，详见 CHANGELOG。运行 `powershell -ExecutionPolicy Bypass -File scripts/package.ps1` 可从标签重新生成三个源码包；输出在 `artifacts/`，不包含依赖、数据库、附件、`.env` 或登录会话。
